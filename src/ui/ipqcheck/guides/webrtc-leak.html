WebRTC 泄漏如何判断？出口与候选地址说明

维护：Ping100 · 更新于 2026-10-26

WebRTC 可以通过 ICE 候选地址提供连接信息。若观察到预期代理路径以外的公网出口，应检查浏览器与网络路由；私网地址或 mDNS 名称本身不等于公网 IP 泄漏。

01检测步骤

记录网页连接的公网 IPv4/IPv6，运行浏览器检测并检查 WebRTC 候选地址。对比直连与代理状态，区分私网、服务器反射和中继候选，确认不一致地址是否属于你的直连出口。

02为什么可能绕过代理

部分代理只处理网页流量，WebRTC 的 UDP 连接可能使用其他网络路径。是否出现不同出口取决于浏览器策略、系统路由与代理方式。RFC 8828 讨论了这些隐私与连接能力之间的取舍。

03如何处理

优先检查代理或隧道是否覆盖 UDP 与 IPv6，再检查浏览器的 WebRTC IP 处理策略。修改后复测，并验证视频会议等功能；限制候选地址可能影响通话连接。

04没有候选地址能证明安全吗

不能。浏览器限制、权限、扩展和网络阻断都可能使测试无法收集候选。一次测试只说明当前环境下可见的信息。

参考：RFC 8828：WebRTC IP Address Handling Requirements。本文排查步骤为本站实践建议。
