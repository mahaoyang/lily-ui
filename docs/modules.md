# 模块规范

按能力划分无头模块，按职责拆开浏览器适配、UI、主题和应用。主题与功能不互相包含。

| 模块 | 职责 | 允许依赖 |
| --- | --- | --- |
| `headless/<领域>` | 数据模型、规则、状态、客户端工厂、生命周期 | 无头模块、标准 JavaScript、注入服务 |
| `adapters/browser/<领域>` | 浏览器采集、存储、文件编码、Worker 和服务实例 | 无头模块、其他适配器、浏览器 API |
| `ui/<应用>` | DOM 组件、页面控制器、导航、翻译、模板与交互 | UI 模块、无头模块、浏览器适配器 |
| `themes/<主题>` | CSS、视觉资源与语义颜色 | CSS 与视觉资源，不包含可执行 JS |
| `apps/<应用>` | HTML 页面入口、功能入口与主题选择 | UI、主题、适配器、无头模块 |
| `scripts` | 本地开发、代理、构建与检查 | Node.js 标准库 |

UI 不导入主题或应用入口；主题不导入功能。应用 HTML 同时选择 UI 入口和 CSS，使用 DOM 结构、class、data 属性及语义色变量作为外观契约。切换外观时无需把业务逻辑复制进主题目录。各产品的 DOM 结构尚不统一，因此现有主题不能保证跨产品直接互换。

主题选择由应用设置以明确选项承载，可提供“跟随系统 / 浅色 / 深色”三态；不在右上角提供主题切换 toggle。主题实现只响应应用设置写入的外观状态。

外部项目参考本项目时，应将需要的模块复制到外部项目后再按其需求修改；不要为了适配外部项目而改动本项目代码。若发现本项目确有通用改进，应作为本项目自身的独立变更提出，并保持模块边界与现有应用契约。

浏览器适配层不导入 UI、主题或应用。工作流的运行时服务集中在 `adapters/browser/workflow/runtime.js`，检测服务在 `adapters/browser/diagnostics/runtime.js`，Fox 和 FinPri 客户端分别位于 `adapters/browser/fox/client.js` 与 `adapters/browser/browser-manager/client.js`。请求、存储和环境能力经工厂注入无头实现。

## 无头领域

- `fox`：特有会话协议、模型配置、用量与资源状态。
- `diagnostics`：IP 情报、评分、泄漏、浏览器真实性、网络与检测批次。
- `workflow/graph`：拓扑、节点、复合节点、重试、审核项身份。
- `workflow/runtime`：任务池、任务命名、客户端与事件订阅。图和存储行为通过注入获得。
- `workflow/persistence`：输入快照存取与编码契约。
- `audio`：频谱计算、预览处理与音色混合，不依赖工作流执行。
- `controls`：折叠面板、标签页和弹窗状态，不包含 DOM、焦点或滚动控制。
- `browser-manager`：环境配置、代理链接、地区语言和 API 契约。
- `text`：字数与字符统计。
- `color`：sRGB 到 OKLCH 转换及格式化，无 DOM、主题选择或业务依赖。

各领域 `index.js` 是外部入口，由包 exports 暴露；内部按需引用实现。`headless/index.js` 保留原 Fox 兼容入口。不同契约的客户端不为目录对称而合并；不抽取依赖隐式 DOM 状态的伪通用模块。

## 视觉与 OKLCH

`themes/shared/colors.css` 提供危险、警告、成功和焦点的统一 OKLCH 色角色，分别指定浅色和深色值。各主题使用 `--lily-background`、`--lily-surface`、`--lily-text`、`--lily-muted`、`--lily-border`、`--lily-accent` 描述核心视觉；旧变量通过别名接入，逐步迁移控件时继续使用这些语义。核心十六进制色已转换为等价 OKLCH，保持原有色彩。主题仍保留阴影、几何和装饰色，不宣称所有颜色都已统一。

`color-roles.css` 将产品状态变量连接到共享色角色。颜色计算和 CSS 分别独立导出；无头功能不读取 CSS，主题不加载计算代码。AI Flow 仅保留浅色；Fox 与 FinPri 的深浅模式保留。

## 运行与验证

开发服务按应用入口、UI 和主题资源组合原公共 URL；构建复制分层模块并组合静态资源。每套产物独立部署在域名根目录。FinPri 的在用旧版编辑器继续保留在 UI，不因 legacy 名称删除功能。

`npm run verify` 检查语法、本地引用、包入口、依赖边界、行为测试及四套构建。真实检测、推理和浏览器启动需要原后端。检测继续区分缺失、不支持、超时与成功，刷新隔离旧响应，取消能力不得丢失。
